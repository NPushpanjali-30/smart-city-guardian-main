# Smart City Guardian: Integration Failure Matrix (Phase 8)

This matrix specifies the failure behaviors, detection mechanisms, automated fallbacks, and recovery procedures across all system components.

| Component / Subsystem | Failure Scenario | Detection Mechanism | Automated Fallback / Mitigation | User / System Impact | Recovery Procedure |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Open-Meteo Weather API** | HTTP 500, timeout ($> 3000\text{ms}$), or DNS failure | `CircuitBreaker` failure counter ($\ge 3$ errors) | Fallback to deterministic local mock weather model | System continues risk evaluation using last known good observation or conservative mock estimates. | Circuit breaker enters `HALF_OPEN` after 30s cooldown; probes upstream health automatically. |
| **TomTom Traffic API** | Rate limited (HTTP 429) or upstream outage | `CircuitBreaker` failure counter | Revert to static road network speed limits and historical congestion curves | Traffic delay factor defaults to $1.0\times$; incident hazards still evaluated from municipal feed. | Auto-resets upon successful response in `HALF_OPEN` state. |
| **xAI Grok API** | Upstream latency ($> 8000\text{ms}$), invalid JSON, or auth failure | Try-catch in `GrokDecisionService` + Zod schema validation in `GrokResponseValidator` | Instantaneous hand-off to `GrokFallbackService` | Zero downtime. EOC operators receive deterministic rule-based advice instead of LLM reasoning. | Automatically re-engages live Grok provider on next request without restart. |
| **Twilio SMS Provider** | Network failure, invalid credentials, or quota exhaustion | HTTP response error code or unconfigured credentials check in `TwilioSmsAdapter` | Graceful failure logging; marks notification as `FAILED` in queue; preserves message in history | Commuter does not receive SMS; notification remains visible in citizen mobile web app via WebSocket/polling. | Queue retry mechanism re-attempts transient failures up to 3 times before terminal failure. |
| **OSRM Routing Engine** | Service unreachable or no valid path found between points | HTTP error / empty routes array in `osrmRoutingProvider.ts` | Fallback to heuristic A* graph routing engine over local road topology | Navigation continues seamlessly with slightly simplified geometric path. | OSRM adapter re-attempts live endpoint on subsequent route requests. |
| **Realtime WebSocket Server** | Sudden client disconnection or network partition | Heartbeat ping/pong timeout ($> 30\text{s}$) or `socket.on('close')` | Session preserved in memory; buffered events queued; connection cleaned up gracefully | Commuter app falls back to REST API polling ($5\text{s}$ interval) until reconnect. | Client auto-reconnects with exponential backoff; re-subscribes to session and topics. |
| **Active Route Session** | Client sends malformed coordinates or invalid session ID | Zod schema validation in `routing.router.ts` | Immediate `HTTP 400 Bad Request` or `HTTP 404 Not Found` response | Request rejected; existing session state unaffected. | Client re-transmits valid request format. |
| **Tenant Privacy Violation** | User B attempts to stop or modify User A's navigation session | Session ownership check: `session.userId !== requestingUserId` | Immediate `HTTP 403 Forbidden` response and structured warning log | Unauthorized modification blocked; zero data leakage. | Request discarded. Client must provide matching credentials. |
| **Concurrent Evaluation Race** | Multiple simultaneous calls to `evaluateAllRoadRisks()` | Shared `activeEvaluationPromise` in `RoadRiskService` | Coalesces concurrent calls into single shared in-flight Promise | Eliminates redundant CPU/memory overhead and prevents empty state flashes. | Promise completes and resolves identical authoritative snapshot to all callers. |
| **Anti-Spam Alert Storm** | Rapidly oscillating flood readings trigger repeated warnings | `NotificationPolicyService` 30-minute cooldown + geographic deduplication | Rejection code `COOLDOWN_ACTIVE` or `DEDUPLICATED` | Citizen protected against notification spam; only 1 SMS sent per hazard cycle. | Cooldown automatically expires after 30 minutes or immediately if hazard escalates to `CRITICAL`. |
